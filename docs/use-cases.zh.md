# 潜在典型应用场景

[English](use-cases.md) | 中文

本文以合成示例说明潜在典型应用场景，不代表已部署客户案例、已实现功能或行业合规认证。实现边界以 [v0.1 契约](v0.1-contract.zh.md)为准。

## 一句话定位

当智能体需要把不同时间、不同话题中的经历关联起来，而不是只保留最近几轮对话时，tapestry-memory 可作为模型外部的关系记忆层。宿主控制写入、权限与回答，引擎承担图数据存储和有界检索；两者的责任不能混淆。

记忆节点可以表达一次事件、明确偏好或经过确认的事实；关系边可以表达宿主提供的关联。引擎不应被宣传为自动识别真相、自动理解所有关系或保证永不遗忘。来源定位键用于追溯，不等于证据真实。

## 场景总览

| 场景 | 值得保留的内容 | 预期价值 | 明确不替代 |
| --- | --- | --- | --- |
| 陪伴产品 | 用户主动确认的称呼、偏好、共同经历和后续话题 | 减少重复自我介绍，让跨会话交流连续 | 心理治疗、危机处置或情感依赖设计 |
| 客服智能体 | 经授权的工单经历、处理步骤、设备关联和未结事项 | 接续上次服务并提供可追溯上下文 | CRM、实时订单系统、权限系统或业务真相源 |
| 教育智能体 | 学习目标、已掌握概念、错题关系和近期反馈 | 围绕学习轨迹选取相关解释与练习 | 学业定论、心理画像、正式评分或教师判断 |
| 机器人交互 | 经许可的称呼、交互习惯、设备间连续经历 | 在更换交互终端后保持对话背景连续 | 运动控制、安全规划、实时感知或意识证明 |

## 陪伴产品：连续，而非黏住用户

示例：用户曾说喜欢简短的睡前故事，之后又主动分享了一次旅行。下次谈到那次旅行时，宿主检索相关经历与叙述偏好，为模型提供带来源的上下文，而不是把全部历史塞进提示词。

建议写入经过同意的偏好与有价值的事件；单轮情绪推测、未经确认的人格标签和模型自己编出的事实不应直接固化为用户记忆。用户改口时由宿主确认新旧关系，不能假定引擎会自动解决冲突。

验收重点：跨会话事实引用是否正确，更新后的偏好是否覆盖旧建议，删除后是否仍被提起；同时关注错误记忆率，而不只看记住多少。允许用户查看、纠正、删除或关闭记忆，不用记忆制造排他关系或施压留存。

## 客服：记得处理经过，实时系统决定业务事实

示例：用户第二次询问一台设备的故障。宿主先完成身份与权限校验，读取最新工单和保修状态，再用记忆层补充上次排查步骤及关联症状。回答应明确区分当前业务事实与历史处理记录。

客户资料与公共知识必须显式分域。namespace只能是待验证的库级数据作用域，不能替代宿主身份认证与授权。跨客户遍历、同内容去重串域和跨域删除必须有专项测试；安全边界未通过前，不用于共享库多租户生产服务。

验收重点：同一问题能否接续处理、过期政策是否被误当现行规则、客户之间是否泄漏、来源是否可定位。优惠、退款、订单修改等操作仍由业务工具和权限策略执行，记忆不能授权操作。

## 教育：记录学习过程，不把学生定型

示例：学生已掌握分数加法，但在单位换算中反复遗漏单位。宿主把实际练习结果关联到概念和讲解经历，下次生成练习时检索相关薄弱点及已有效的解释方式。

记忆应区分学生自述、练习证据和模型推测；保留时间与可更正来源。一次错误不能沉淀为“能力差”的永久标签。未成年人场景需要适用法律下的监护同意、最小化收集与保留期限管理，这些机制由产品实现，不由库自动提供。

验收重点：是否引用真实练习、是否避免重复无效讲解、纠正后的掌握状态是否生效、教师或学生能否更正记录。不能仅凭答题准确率变化宣称提升学习成效，需设计独立评估。

## 机器人：作为交互记忆，不是整套 soul

示例：用户从桌面助手切换到家用机器人，希望延续之前的对话主题与称呼。宿主在身份和设备权限确认后使用同一授权记忆作用域，或者显式导入允许转移的数据；引擎不自行同步设备。

在产品把“soul”用于描述持续身份与交互风格时，tapestry-memory可以是其中的记忆组件，但不包含身份规范、价值策略、情绪系统或完整行为编排。感知输入的可信度、多人识别、数据同步与冲突处理由宿主负责。

验收重点：更换模型或设备后相关经历是否仍可追溯，多人共用设备时是否串记忆，离线重开后持久记录是否可用。物理动作必须经过独立安全控制；历史“可以靠近”不能替代此刻的障碍检测和许可。

## 接入模式与责任划分

推荐流程：获得同意与作用域 → 选择并确认写入内容 → 写入节点及关系 → 按问题有界检索 → 宿主校验来源和时效 → 模型生成 → 必要时更正或删除。该流程是集成建议，不是已实现的API示例。

| 层次 | 责任 |
| --- | --- |
| 产品与宿主 | 身份认证、授权、同意、敏感信息策略、写入抽取、冲突裁决、保留期限、回答与动作安全 |
| 记忆引擎目标 | 作用域内存储、关系遍历、来源元数据往返、持久化及明确的逻辑删除契约 |
| 外部系统 | 订单和知识真相源、原始文档访问、备份、设备同步、可选模型或向量服务 |

删除图中的节点不自动删除外部原文、日志或备份；来源元数据也不授予访问原文的权限。重要回答仍应回查业务真相源，不能把“以前说过”当成“现在正确”。

## 适合与不适合

优先考虑需要跨会话、跨事件关联的个人助手和规模可控的嵌入式应用。开发者需要愿意定义何时写入、如何关联，以及什么应被遗忘。只需固定偏好时，配置文件或简单键值表可能更合适。

不应直接用于未经规模验证的大型共享图、海量文档搜索的唯一检索层、临床或法律决策依据，以及实时运动控制。当前没有公开包的吞吐量、延迟或节点规模承诺，不能把内部试验规模当成服务等级协议。
