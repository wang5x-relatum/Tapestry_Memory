# v0.1 contract

English | [中文](v0.1-contract.zh.md)

Status: stage-2 behavioral contract for the local `tapestry-memory` implementation, intended for version 0.1.0. The public API below is the agreed implementation contract, not a claim that acceptance tests or artifact validation have passed. This document is the behavioral source of truth; source-project results do not substitute for standalone-package acceptance. Bilingual human review remains pending after edits.

## Scope

The core covers embedded graph memory: nodes, directed edges, namespaces, persistence, bounded relationship retrieval, and logical deletion. Runtime uses Python 3.10+, the standard library, and SQLite, with no third-party runtime dependencies, no network access by default, and no imports from Relatum internals. The package excludes host personality, value policy, model calls, conversation-source replay, and robot action orchestration.

Stage 2 excludes automatic relation extraction, automatic conflict arbitration, multi-device synchronization, distributed services, arbitrary-scale guarantees, 500-character truncation, GDPR-complete deletion, and default embeddings. No matching callback or semantic ranking is promised by the API below.

## Data and identity

Public types are imported from `tapestry_memory`. A `Node` has `id`, `content`, `metadata`, `created_at`, and `weight`. An `Edge` has `source`, `target`, `relation`, `weight`, `count`, and `created_at`. IDs are generated UUID4 strings; there is no caller-supplied node-ID API. Node primary identity is `(namespace, id)` and never includes a content hash. Identical content produces independent nodes both within and across namespaces.

Content is a string, including empty strings and strings longer than 500 characters, without truncation. Weights accept nonnegative integers or floats, excluding booleans, and are converted to finite floats; nonfinite values and conversion overflow raise `ValueError`. Edge counts are integers in `1..2**63-1` (signed 64-bit range), excluding booleans. Creation timestamps use UTC ISO 8601 with microseconds and `+00:00`; updates preserve creation time. Edges are unique by scoped directed `(source, target, relation)`; writing a duplicate replaces weight and count rather than incrementing them, preserving creation time.

Metadata is a dictionary of strict native JSON values: string keys, dictionaries, lists, strings, booleans, integers, finite floats, and null. `None` as the metadata argument means `{}`. Tuples, sets, custom values, cycles, and nonfinite floats are rejected. Updating metadata replaces the whole dictionary rather than merging. Optional nested `provenance` is preserved through write, database close/reopen, and retrieval without loss of JSON values. No `r:/c:` format is required, no source file or URL is automatically opened, and provenance is not truth verification.

## Namespace and deletion

`MemoryStore(path=':memory:', *, namespace='default')` fixes a read-only namespace for that store. Omission selects `default`; explicit `None`, empty strings, whitespace-only strings, and nonstrings are rejected with `ValueError`. Other namespace strings are preserved exactly, not trimmed. Namespaces constrain all reads and writes, seed lookup, each neighbor expansion, both edge endpoints, results, updates, and deletion. There is no implicit global/shared scope or namespace-deletion API. Library isolation does not replace host authentication and authorization.

Logical deletion removes a node and its incident edges from the active graph within that namespace; deleted data must not reappear through getters or traversal. Package-owned derived data must be removed and package caches invalidated when present; stage 2 has neither derived data nor a cache. Edge deletion affects only the specified scoped directed triple. Other namespaces remain unchanged. This is logical deletion at the library interface, not a promise of physical storage erasure, external-source deletion, host-log deletion, backup deletion, or GDPR-complete deletion.

## Public methods and mutation semantics

The following signatures define the public surface; `...` denotes an omitted update field, not a value to pass. Omitted update fields remain unchanged.

```python
MemoryStore(path=':memory:', *, namespace='default')
store.add_node(content, *, metadata=None, weight=1.0) -> Node
store.get_node(node_id) -> Node | None
store.update_node(node_id, *, content=..., metadata=..., weight=...) -> Node
store.delete_node(node_id) -> bool
store.add_edge(source, target, relation, *, weight=1.0, count=1) -> Edge
store.get_edge(source, target, relation) -> Edge | None
store.delete_edge(source, target, relation) -> bool
store.retrieve(seed_ids, *, top_k=10, max_depth=2,
               traversal_budget=1000) -> RetrievalResult
store.transaction()
store.close()
```

Missing getters return `None`; deleting an absent item returns `False`. Updating an absent node or adding an edge with a missing, deleted, or foreign endpoint raises `KeyError`. Invalid public inputs raise `ValueError`. All writes are atomic. `transaction()` groups writes with rollback on failure; nesting uses savepoints so an inner failure can roll back without losing outer writes when caught. An uncaught outer failure rolls back the outer transaction. `MemoryStore` as a context manager closes the connection on exit; use `transaction()` explicitly to define a grouped transaction, not the store context manager.

Committed data must survive reopening the same file-backed database. Failed transactions must leave no partial node, edge, or metadata updates after reopen. Closing the default `:memory:` store does not promise persistence; reopen checks use a database file.

## Bounded deterministic retrieval

`retrieve` returns `RetrievalResult` with `nodes` (a tuple), `visited_count`, `traversed_edges`, and `budget_exhausted`. Retrieval uses outgoing directed breadth-first traversal, not weight ranking or five-dimensional scoring. Seeds retain input order with duplicates removed; valid seeds are included at depth 0. Nonexistent, deleted, and foreign seeds are ignored. Neighbors are ordered lexically by target ID, then relation. Determinism means the same stored graph and ordered seed input yield the same traversal, not that independent UUID creation yields identical order.

`top_k`, `max_depth`, and `traversal_budget` must be integers greater than or equal to zero, excluding booleans; their defaults are 10, 2, and 1000 respectively. `max_depth` bounds expansion depth. `top_k` caps returned nodes only, not traversal; `visited_count` can exceed the returned tuple length. The traversal budget counts every examined edge, including edges targeting already visited nodes. `traversed_edges` reports that count. `budget_exhausted` is true only when the budget prevents examining a further eligible edge; reaching the numeric limit exactly with no eligible edge left is not exhaustion. Partial results must not be represented as exhaustive traversal. Isolation applies throughout traversal, not only when filtering final results.

Seed ingestion is O(number of supplied seeds) and is outside the edge traversal budget; callers must supply a finite iterable and bound its size themselves. `top_k=0` still traverses and counts, `max_depth=0` never expands, and `traversal_budget=0` still includes valid seeds but reports exhaustion only if an expandable outgoing edge exists.
