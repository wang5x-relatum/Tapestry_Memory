# 双语文档规则

[English](README.md) | 中文

状态：设计基线。本规则约束仓库中的英文和中文技术文档；不宣称能够完整解析 Markdown 或验证语义翻译。

## 三文件配对

每份纳入检查的文档都是同级三文件：

- `name.md` 是英文正文。
- `name.zh.md` 是中文正文。
- `name.i18n.yaml` 记录两份 Markdown 最近一次人工复核对应的 Git blob hash。

中英文同权。任一语言发生变更，都必须复核另一份并更新一致性记录。YAML 记录的是 blob hash，不是 commit hash，也不是翻译快照。

## 机械检查范围

本地检查器只验证它明确承诺的规则：

- 每份纳入范围的英文文档都有中文文档和 YAML 记录；
- 两份 Markdown 的标题、列表、表格、代码围栏和本地链接结构一致；
- H1 后的语言切换链接指向对应文档；
- 本地链接存在且位于仓库内部；
- 一致性记录包含当前两份文件的完整 Git blob SHA-1 值。

检查器有意采用标准库实现的轻量子集，不是完整 Markdown 解析器。它不能判断翻译质量、术语、事实等价性、授权或产品安全。检查通过只代表机械规则通过。

## 复核与记录流程

1. 同时编辑英文和中文文档。
2. 运行 `python3 scripts/check_docs.py`，发现结构或 hash 漂移。
3. 由人工复核两种语言的含义、术语和自然度。
4. 对明确完成复核的英文路径运行 `python3 scripts/check_docs.py --record path/to/name.md --reviewed`。
5. 再次运行检查器，并在同一变更中提交三份文件。

`--record` 必须同时带 `--reviewed`，且只接受显式英文 Markdown 路径，不是对所有文档的批量盖章。

## 术语

稳定技术术语参见[术语表](terminology.md)。产品表述仍需审核；“机器人交互记忆”和“soul”等词不能把包的边界扩展到契约之外。
